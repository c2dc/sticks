## ⚡ Commands

Run from the repository root. Only PostgreSQL runs in a container. Backend and frontend run natively with hot reload.

| Command | Does |
|---------|------|
| `npm run db:up` | Starts only the `postgres` container |
| `npm run setup` | One time: backend venv and frontend dependencies |
| `npm run db:migrate` | Applies the Alembic migrations |
| `npm run dev` | Migrations, then backend (uvicorn `--reload`, `:8010`) and frontend (Vite, `:8000`) |
| `npm run dev:backend` / `dev:frontend` | Same, one side only |
| `npm run dev:containers` | Optional: backend and frontend as containers. Not the default |

> [!WARNING]
> `uvicorn --reload` restarts the backend on any change under `apps/backend/app`, which kills a run in progress.
> At the next start the Reconciler marks that run `failed` (`interrupted_by_restart`) and its Caldera operation `aborted`.
> A run paused in `awaiting_approval` survives a restart.

## 🔧 Configuration

Set in the root `.env` (never committed). The backend also reads the process environment.

| Variable | Purpose | Default |
|----------|---------|---------|
| `SEPINF_BASE_URL`, `SEPINF_MODEL_ID`, `SEPINF_API_KEY` | Work language model (OpenAI-compatible). Needs the work VPN | none |
| `OLLAMA_BASE_URL` | Ollama, for local models and embeddings | `http://127.0.0.1:11434` |
| `OLLAMA_EMBED_MODEL` | Embedding model | `nomic-embed-text` |
| `AI_EMBEDDING_DIM` | Width of `experience_memory.embedding`. Must match the model | `768` |
| `AI_MAX_ITERATIONS` | Refinement loop bound | `3` |
| `AI_RETRIEVAL_K` | Vector retrieval top-k | `5` |
| `STICKS_INGEST_ON_START` | Automatic ingestion at start | `true` |
| `STIX_VERSIONS` | Pin the STIX versions (comma separated, `latest` allowed). Replaces only the "newest" item | newest + 18.0 |
| `ATTACK_FLOW_REF` | Git tag of the Attack Flow corpus | pinned tag |
| `GITHUB_TOKEN` | Optional, raises the GitHub rate limit | none |
| `INGEST_WORK_DIR` | Absolute folder for ingestion temp files (use one with an antivirus exception). Unset means in memory | unset |
| `ATOMIC_MIN_TECHNIQUES` | Plausibility floor for Atomic Red Team. Fewer ends `failed` | `100` |
| `DOCKER_CATALOG_MIN_IMAGES` | Completeness floor for the image catalog | `150` |
| `DOCKER_CATALOG_MIN_PULLS` | Minimum pulls for a non-official image | `100000` |
| `OLLAMA_EMBED_TIMEOUT` | Seconds per embedding request | `120` |
| `LLM_CONNECT_TIMEOUT_SECONDS` / `LLM_READ_TIMEOUT_SECONDS` | Model client limits. No automatic retry | `5` / `180` |
| `LLM_PREFLIGHT_RESPONSE_TIMEOUT_SECONDS` | One-token test call of the pre-start check | `120` |
| `OPERATIONALIZATION_NEGOTIATION_MAX_ROUNDS` | Operationalization ↔ Environment rounds | `1` |
| `RUN_SUCCESS_COVERAGE_MIN` | Coverage the evaluator compares against | see code |

An invalid, zero or negative timeout falls back to its default.

## 📥 Ingestion notes

Order: `stix_packages` → `curated_seed` → `atomic` → `docker_catalog` → `attack_flow`. Status at `GET /api/ingestion/status`.
`POST /api/ingestion/verify` re-checks, and `POST /api/ingestion/atomic/start` forces Atomic.

| Source | Good to know |
|--------|--------------|
| **STIX** | Downloaded into memory, about 50 MB per version. A fresh install takes the newest version and 18.0 (needed by the curated cases). The UI can request more: `POST /api/stix/bases/{version}/download` (202). The version list is cached for 1 h and falls back to the built-in list offline |
| **Atomic Red Team** | Tarball streamed from `codeload.github.com`, only `atomics/T####/T####.yaml` is read. Commands are saved first, then vectorized in batches of 32. A truncated download is retried, never accepted. `manual` tests are dropped. A malformed YAML file is skipped and reported, not fatal |
| **Docker catalog** | Text only from the Docker Hub API (about 1600 images, all marked `linux`, since Docker Hub has no official Windows images). The anonymous API serves 200 results per query, so the catalog is built from several short queries. Failed queries become warnings. It fails only if no image arrived |
| **Attack Flow** | `.afb` flows from a pinned tag. Cycles are logged, an acyclic execution view is derived |
| **Curated seed** | Local JSON, no network. Rows edited or generated by AI are never overwritten |

**Command templates.** `technique_commands` keeps the Atomic text byte for byte, with `#{name}` placeholders and each argument's default.
Defaults are suggestions only. The operationalization agent chooses IPs, hosts and paths for the campaign and answers with
`{template, command}` items. A command is accepted only if its template is in the technique's pool and no `#{...}` or
`PathToAtomicsFolder` remains. Otherwise a deterministic fallback fills the Atomic defaults and the trace records
`atomic_defaults`.

If Ollama fails, the relational part stays complete and the next verification only vectorizes what is missing.

**Curated seed maintenance** (from a database that already holds the curated cases, read only):

```bash
python ops/database/scripts/export_curated_seed.py --output-dir apps/backend/app/seeds/data
```

It fails if the counts differ from 8 campaigns, 108 abilities and 8 adversaries. Details in [`ops/database/README.md`](../ops/database/README.md).

## 🧠 Model profiles and the pre-start check

The agents use one language model, the **selected profile**. Profiles are discovered, not registered.

| Profile | Built from |
|---------|-----------|
| **Work** (default) | `SEPINF_*` variables. Needs the VPN |
| **Local** | One per text-generation model listed by `GET {OLLAMA_BASE_URL}/api/tags`. If Ollama does not answer in 2 s, only the work profile is offered |

`PUT /api/llm/selection` stores the choice in `preferences.llm_profile_id`. The API key stays in the environment. It is never stored, returned or logged.

`POST /api/llm/preflight` (cached 30 s per profile) runs before a run starts, and again on approve and regenerate:

| Check | Codes |
|-------|-------|
| Reachability | `reachable` / `unreachable` |
| Response (one token) | `responds` / `no_response` |
| Ollama daemon and model | `daemon_running` / `daemon_down`, `model_present` / `model_missing` |
| Memory (local models) | `fits_gpu`, `fits_ram_only`, `too_large`, `memory_unknown` |
| Embedder | `embedder_available` / `embedder_missing` |

A local model fits when its size times 1.2 is at most the free GPU memory (read with `nvidia-smi`), then the free RAM.

- 🔴 **Blocks** (409 `llm_blocked`, no run created): not configured, unreachable, no response, daemon down, model missing, `too_large`.
- 🟡 **Warns only**: `fits_ram_only`, `memory_unknown`, `embedder_missing` (agents then run without the embedding memory).
- 🔴 **Fails during a run**: 503 `run_failed` with `cause_code` `llm_unreachable`, `llm_timeout`, `llm_not_configured`, `llm_error` or `run_error`.

## 🗃️ Migrations and backups

`npm run dev` and `npm run db:migrate` apply Alembic migrations. Back up before pulling a change that adds one:

```bash
docker exec sticks-postgres pg_dump -U pipeline_ui -Fc pipeline_ui > sticks-backup.dump          # backup, write it outside the repo
docker exec -i sticks-postgres pg_restore -U pipeline_ui --clean --if-exists -d pipeline_ui < sticks-backup.dump   # restore
```

- Finish running agent executions first. LangGraph checkpoints are not migrated, so a run started before an upgrade cannot resume after it.
- Roll back one migration with `alembic downgrade <revision>` from `apps/backend`, with `PIPELINE_UI_DATABASE_URL` set.
- The phase-name migration `b0c1d2e3f4a5` renamed `stage_*` tables to `phase_*` and the phase number column to a phase name. If a downgrade stops because a value has no numbered equivalent (for example `evaluation`), restore the dump.

## 🧪 Development checks

```bash
# Backend, from apps/backend (Windows: .venv/Scripts/python, Linux/macOS: .venv/bin/python)
python -m pytest
python -m ruff check .
python -m ruff format --check .

# Frontend, from apps/frontend
npm run lint:eslint    # ESLint 9
npm run lint           # tsc --noEmit
npm run test           # vitest
```

- The repository keeps **10 tests** on purpose (8 backend, mostly Hypothesis with 10 examples, and 2 frontend). New tests need the owner's approval. See `.kiro/steering/`.
- Suppressions need a reason: `# noqa: BLE001 -- <reason>` or `// eslint-disable-next-line <rule> -- <reason>`.
- mypy is not used. There is no CI and no pre-commit hook, so run the checks by hand.
- `ops/` holds the vendored Caldera and is never linted.
- After changing frontend dependencies, update both `package-lock.json` files (root and `apps/frontend`).

## 🐳 The lab

Caldera, the Kali attacker and the nginx and MariaDB targets are **not started by hand**. The `environment` phase builds and starts them
(`caldera-attacker`, `kali-attacker`, `nginx-target`, `mariadb-target`), cuts external egress and verifies it.

| Network | Subnet | Hosts |
|---------|--------|-------|
| `caldera-kali-network` | `192.168.10.0/24` | caldera `.10`, kali `.20` |
| `kali-nginx-network` | `192.168.20.0/24` | kali `.20`, nginx `.30` |
| `nginx-db-network` | `192.168.30.0/24` | nginx `.30`, db `.40` |

**Validate from scratch.** Keep only `sticks-postgres`. Remove the `sticks-*` lab containers, the volume `sticks-mariadb-target-data`,
the lab networks and, for a full rebuild, the lab images. Never remove `sticks-postgres` or its volume. Then start a run and approve the
attack flow. The first build takes tens of minutes, mostly Caldera (image about 7.3 GB, check with `docker system df`).

Caldera UI: <http://localhost:8888>, only while the lab is up.
